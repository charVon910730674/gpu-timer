## 1. 需求演进（一天 6 轮迭代起步，后续持续加报表）

| 版本 | 需求 | 关键变化 |
|---|---|---|
| v1 | 裸金属使用计费系统 | 按资源明细计费（GPU/CPU/内存/存储） |

| v6 | 在线判定细化 | GPU 在线 + 无 XID + IPMI 电源（三条件） |
| **v7** | **7 条件在线判定** | IPMI电源 ∧ 机器正常 ∧ GPU在线 ∧ 无不可纠正错误 ∧ 无XID ∧ IB网络 ∧ IB端口 |
| **8-13** | 硬件故障内迁 | 10 条件：+ 内存/磁盘/CPU 硬件故障 + IB 卡数量（见 §5） |
| 8-20 | 口径修正 | mem_fault 改 EDAC 增长量 + HardwareCorrupted；cpu_fault 只按 type=Processor |

## 2. 系统架构（终版）

```
Prometheus(IPMI+node+DCGM+IB, 250) ─▶ gpu-timer 容器(Python, APScheduler)
    │ 5min 采集 10 条件判定 + 负载/温度顺带采集    │
    ▼                                          ▼
MySQL(gpu_timer 库) ◀── 快照/事件/时段/负载采样   ├─ 5min 采集器（10 条件 + util_samples）
    ▲                                          ├─ 1h session 重建
    │                                          ├─ 6h 机器同步
Superset 看板(dashboard 5) ◀── MySQL 视图        ├─ 每日 01:00 日报 + 01:05 故障明细
Prometheus 告警规则(告警页) ◀── 实时指标          ├─ 每日 01:10 CPU TOP20 + 01:12 GPU(全量) + 01:14 高温
                                                └─ 每月 1 日 02:00 月报
```

## 5. 在线判定（10 条件，实际指标映射全部验证）

| # | 条件 | 指标 | 说明 |
|---|---|---|---|
| 1 | IPMI 电源 | `ipmi_chassis_power_state==1` | 198.51.100.x = BMC 网段（末位对应节点段 203.0.113.x）；无 IPMI（94 号）用探活兜底 |
| 2 | 机器正常 | `up{job="node_exporter"}==1` | |
| 3 | GPU 在线 | `count(DCGM_FI_DEV_GPU_UTIL) by (instance) > 0` | 712 卡/89 台 |
| 4 | 无不可纠正错误 | `UNCORRECTABLE_REMAPPED_ROWS==0 ∧ ROW_REMAP_FAILURE==0` | |
| 5 | 无 XID | `count(DCGM_FI_DEV_XID_ERRORS)==0` | 事件型指标：正常无序列，有序列即错误 |
| 6 | IB 网络 | `ib_global_status==1` | 缺失视为 OK（设计） |
| 7 | IB 端口 | `min(node_infiniband_state_id) by (instance)==4` | 全部端口 active；缺失视为 OK |
| 8 | 内存硬件 | `increase(EDAC_uncorrectable[1h])>0` 或 `increase(EDAC_correctable[1h])>10` 或 `HardwareCorrupted_bytes>0` | **8-20 起**：增长量口径，IPMI 内存传感器已移除 |
| 9 | 磁盘硬件 | IPMI `type="Drive Slot"` 或 name 含 NVME/HDD/SSD/DISK/RAID 传感器 !=0 | |
| 10 | CPU 硬件 | IPMI `type="Processor"` 传感器 !=0 | **8-20 起**只按 type 匹配（排除 CPU Usage） |
| — | IB 卡数量 | `count(node_infiniband_physical_state_id{device=~"mlx5_[0-9]+"}==5) >= 8` | 无序列视为 OK；<8 → `ib_card_missing` |
| 附 | 负载/利用率 | node_load1 / 核数 / GPU util avg·max | 8-22 起顺带采集，**不参与判定**，写 util_samples |
| 附 | GPU 温度 | avg·max(DCGM_FI_DEV_GPU_TEMP) + 最热卡 gpu/UUID | 8-27 起顺带采集，写 util_samples |

**状态机**：全部满足 → online（计时）；电源开但条件 2~10 失守 → fault（不计时，fault_reason 记录全部失守条件，可多值 `+` 拼接）；电源关/不可达 → offline。
**fault_reason 枚举**：`machine_down / gpu_down / gpu_uncorrectable / xid / ib_link_down / ib_port_down / mem_fault / disk_fault / cpu_fault / ib_card_missing`

## 9. 关键技术决策

1. **快照落 MySQL**（不依赖 Prometheus 15 天保留期）——计时数据自持，Prometheus 只做采集源
2. **防抖状态机**：连续 2 点确认翻转才记事件；session 由快照重放生成（幂等，可随时重建）
3. **fault_reason 细分可多值**：失守条件全记录，可追溯
4. **MySQL 视图供 Superset**（而非 SQL 虚拟数据集）——避开 MySQLdb 依赖 + 逻辑持久
5. **142 中转构建**：无外网环境的镜像交付链路（save|gzip|load 管道）
6. **容器内代码挂载** /opt/gpu-timer/app——改代码即生效，重启容器加载（小迭代免重建镜像）
7. **故障检测双轨制**：collector 10 条件写库（看板） + Prometheus 告警规则（告警页）并行，口径一致（EDAC 表达式两处同步维护）
8. **时间戳 300s 网格对齐**（epoch %300 == 0 = 东八区 5min 边界）：回填/修复幂等，杜绝同一时刻多套数据叠加（8-27 两次大规模数据修复都靠它）
9. **存量数据补列用 `ON DUPLICATE KEY UPDATE ... IF(NULL)` 合并模式**：只补新列不动旧值，先 INSERT 后 RENAME 换表
10. **报表按 MySQL 聚合**（util_samples）而非 Prometheus 实时查——历史可回溯，报表口径与采集一致
11. **采集避免全量 range 超限**：核数用 instant 查询一次、最热卡用逐机小查询——712 series 全量 range 会 422
12. **顺带采集**：负载/温度与 10 条件同一轮 PromQL 批量查询（14 个查询），落库一次事务——不加采集轮次

## 10. 踩坑记录（重要经验，按日期累积）

| 坑 | 解决 |
|---|---|
| 250 无外网（DNS 未配 + 443 不通） | 镜像/依赖全走 142 中转；pip 包从清华源 JSON API 下载（URL 是相对路径要拼全） |
| APScheduler `next_run_time=None` | = **paused 添加，永不触发**（文档原话）→ 删掉该参数；回填数据会掩盖采集停摆（8-12 事故根因） |
| 容器内访问宿主 MySQL 用 127.0.0.1 失败 | 用宿主 IP（203.0.113.250） |
| snap 版 docker 的 /tmp 隔离 | 文件放 /root 不落 /tmp；docker cp 走 /var/snap/docker/common/... 路径 |
| 250 python heredoc 转义炸 | 写脚本文件 scp 过去执行 |
| 回填 near() 传了全局索引 | 应传该机器子索引（否则 99% 误判 gpu_down） |
| `ipmi_sensor_state` 有 NaN | `int(float('nan'))` 抛异常中断整轮采集 → `if v != v: continue` |
| 不同 BMC 传感器命名不同 | type+name 双匹配；8-20 起 CPU 只按 `type="Processor"`（name 含 CPU 会误匹配 CPU Usage） |
| IPMI 内存闩锁传感器（ECC1）告警不灭 | EDAC 绝对值 → 增长量口径（8-13 → 8-20 演进）；collector 同步同口径 |
| 规则重载后 pending 残留 | ~30s 自清，勿误判 |
| dcgm job 名 | 是 `dcgm_exporter` 不是 `dcgm` |
| Superset 缺 MySQLdb | pymysql + `install_as_MySQLdb()`（superset_config.py） |
| SQL 虚拟数据集 500 / MySQLdb 依赖 | 改 MySQL 视图 + 表数据集 |
| fill_util 核数 range 查询 422 | 核数不变 → **instant 查询一次**（8-22） |
| Superset API 401/CSRF | 先 login 拿 session，GET /api/v1/security/csrf_token/ 取 token，POST/PUT 带 X-CSRFToken |
| POST /dataset/{id}/refresh 405 | superset 5.0 无此端点，建表数据集列自动同步，无需 refresh |
| 图表按名查找"新建而非更新" | 改名会新建图表 → **旧图表手动 DELETE**（53/54 教训）；脚本要幂等 |
| fill_util 最热卡 argmax 解包错 | `max(gpus.items(), key=kv[1][0])[1]` 取到 (温度,uuid) 元组 → 先取 [0] 卡号再保留 uuid 解包（8-27） |
| ts 网格不固定（回填带任意秒偏移） | `s_ts -= s_ts % 300` 对齐 300s 网格；重跑幂等（8-27，曾致 util_samples 205 万行膨胀） |
| PromQL 双引号字符串里 `\.` 非法转义 400 | 正则用反引号原始字符串 `` `^10\.112\..*` ``（8-27） |
| docker exec 传 heredoc SQL | 必须 `-i`（8-27） |
| `SELECT state, COUNT(*) FROM ds_current_state GROUP BY state` 结果 1/1 | 视图每 state 只有一行，count(*) 数的是行数；要看 cnt 列（8-12 核对教训） |
| pkill -f 自匹配 | `pkill -f` 会匹配到自己的 bash -c 命令行 → 用 `[x]` 技巧或精确匹配（多次复现） |
| 方言 COUNT(DISTINCT a,b) 逗号被拆 | _split_top_level 拆分谓词 → distinct 时非谓词部分拼回列列表（8-26） |
| PromQL `or` 忽略 `__name__` 标签 | 合并多指标用普通标签（kind）+ label_replace（8-26） |
| superset 表名 API 限 250 字符 | 先建占位名再 DB 直写 UPDATE tables（8-26） |
| 手动 INSERT table_columns 忘带 table_id | 孤儿行（8-26，id 214-227 需 UPDATE 补） |
| sqlglot 拦 `SUM(value, __name__='x')` | FILTER 语法可过校验（8-26） |
| 250 机器周期性失联（8-11/8-20/8-22/8-25 同款宕机模式） | 等待恢复；期间在 142/本机完成实现+本地验证+同步，恢复后统一部署 |
