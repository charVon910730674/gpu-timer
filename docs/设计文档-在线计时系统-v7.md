# 裸金属 GPU 服务器使用计时系统设计（8×H100 · 在线计时）

> 本文档为 2026-08-11 原始设计（v7）。后续演进（8-13 十条件、8-20 fault 口径、8-22 util_samples 负载报表、8-27 温度监控与报表体系）见 [开发记录.md](开发记录.md)，代码以仓库 app/ 为准。
>
> 背景：两江 HPC 集群 GPU 节点，统一规格 **8×H100（8 卡 H100 80G / 128C / 512G 级，IB 高速互联）**。
> 计时口径：**在线即计时**。
> **在线定义（多条件 AND）**：IPMI 电源开 ∧ 机器状态正常 ∧ GPU 在线 ∧ GPU 无不可纠正错误 ∧ 机器无 XID 错误 ∧ IB 网络无掉线 ∧ IB 端口无掉线
> 版本：v7.0（2026-08-11）

---

## 1. 计时模型

### 1.1 核心规则
```
使用时长 = Σ(在线时段)
在线时段 = 一次"上线事件" → 下一次"离线事件"的间隔

online(某时刻) = power ∧ machine_ok ∧ gpu_online ∧ gpu_no_uncorrectable
                 ∧ no_xid ∧ ib_link_ok ∧ ib_port_ok
```

- 统一机型 8×H100，**单一计费单位**：台；单台单价 × 在线时长（计费扩展时）
- 5 分钟采样 + 连续 2 点防抖（10 分钟确认翻转）
- 维护/检修期可标记排除（不计时）

### 1.2 在线判定（7 条件）

| # | 条件 | 指标（待 250 恢复后核对实际名称） | 说明 |
|---|---|---|---|
| 1 | IPMI 电源开 | `ipmi_power_on == 1` | BMC 级优先；无 IPMI 用探活兜底 |
| 2 | 机器状态正常 | `up == 1`（node_exporter 探活） | OS/主机可达，无宕机 |
| 3 | GPU 在线 | 该机 DCGM 指标可采（`DCGM_FI_DEV_GPU_UTIL` 等存在） | 驱动挂/GPU 未识别 → 不满足 |
| 4 | GPU 无不可纠正错误 | `DCGM_FI_DEV_UNCORRECTABLE_TOTAL` 无新增（或 ==0） | ECC 不可纠正错误，硬件级故障 |
| 5 | 机器无 XID 错误 | `DCGM_FI_DEV_XID_ERRORS == 0` | NVIDIA XID 错误码，>0 表示 GPU 故障 |
| 6 | IB 网络无掉线 | IB 链路状态 == active（如 `ib_link_state == 4`） | InfiniBand 网络整体正常 |
| 7 | IB 端口无掉线 | IB 端口状态 == active（如 `ib_port_state == 4`） | 所有 IB 端口正常 |

> 指标名说明：DCGM 系列为 dcgm_exporter 标准指标；IB 状态通常来自 node_exporter textfile（ibstat 脚本）或 Mellanox exporter。**具体指标名以 250 Prometheus 实际采集为准**（恢复后先验证，若无 IB 采集需补 exporter）。

### 1.3 状态机（三态 + 故障原因）

```
┌──────────┐  全部条件满足   ┌──────────┐
│ OFFLINE  │ ─────────────▶ │ ONLINE   │─── 计时（在线时长）
│(关机/断网)│ ◀───────────── │          │
└──────────┘  任一条件失守   └──────────┘
      ▲                            │
      │  电源开但部分条件失守      ▼
      └─────────────┬──────────────┘
               ┌──────────┐
               │ FAULT    │─── 不计时，单独统计"故障时长"
               │(故障)    │    fault_reason 记录原因，可追溯
               └──────────┘
```

| 状态 | 判定 | 计时 | fault_reason（枚举） |
|---|---|---|---|
| ONLINE | 7 条件全满足 | ✅ | — |
| FAULT | 电源开，但条件 2~7 任一失守 | ❌ | `machine_down`(机器异常) / `gpu_down`(GPU掉线) / `gpu_uncorrectable`(不可纠正错误) / `xid`(XID错误) / `ib_link_down`(IB网络掉线) / `ib_port_down`(IB端口掉线) |
| OFFLINE | 电源关/不可达 | ❌ | — |

> 多个条件同时失守时记录全部（fault_reason 可多值，如 `xid+ib_link_down`）。

### 1.4 输出指标
- 每台：在线时长、故障时长（按原因细分）、离线时长、在线率、状态翻转次数、当前状态
- 集群：总在线时长、在线率、故障清单（按原因：XID/不可纠正错误/IB 掉线/GPU 掉线）、长期离线清单（>7 天）、掉电频率

## 2. 架构（复用现有设施）

```
Prometheus(IPMI+node+DCGM+IB) ─▶ 在线状态采集器(5min, 7条件判定+防抖) ─▶ MySQL
        ─▶ 事件引擎(online/fault/offline 事件) ─▶ Session 配对(时段)
        ─▶ Superset 看板(在线时长/故障细分/事件流/离线清单)
        ─▶ 告警(长期离线/GPU故障/IB掉线/反复掉电) — alertmanager
```

| 组件 | 实现 |
|---|---|
| 在线状态采集器 | Python cron，5 分钟查 Prometheus 七条件判定状态，写快照 |
| 事件/Session 引擎 | Python cron，每小时生成事件并配对时段（含 fault_reason） |
| 存储 | MySQL（250 已有 3306）：machines / power_snapshots / power_events / sessions |
| 看板 | Superset（250 已有），5~6 个 dashboard |
| 告警 | alertmanager（9093）：长期离线、GPU 故障（XID/不可纠正）、IB 掉线、反复掉电 |

## 3. 数据库（MySQL）

```sql
CREATE TABLE machines (
  id INT AUTO_INCREMENT PRIMARY KEY,
  hostname VARCHAR(64), ip VARCHAR(32) NOT NULL UNIQUE,
  spec VARCHAR(32) DEFAULT '8xH100',        -- 统一规格
  power_source ENUM('ipmi','probe') DEFAULT 'ipmi',
  project_id INT,                           -- 可选归属
  enabled TINYINT DEFAULT 1
);

CREATE TABLE power_snapshots (              -- 5min 快照（7 条件原始判定，可追溯）
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  machine_id INT NOT NULL, ts DATETIME NOT NULL,
  state ENUM('online','fault','offline') NOT NULL,
  power_on TINYINT, machine_ok TINYINT,
  gpu_online TINYINT, gpu_uncorrectable TINYINT, xid_error INT,
  ib_link_ok TINYINT, ib_port_ok TINYINT,
  fault_reason VARCHAR(64),                 -- 如 'xid' / 'ib_link_down' / 'xid+ib_link_down'
  src ENUM('ipmi','probe'),
  UNIQUE KEY uq_machine_ts (machine_id, ts)
);

CREATE TABLE power_events (                 -- 状态翻转事件
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  machine_id INT NOT NULL,
  event_type ENUM('online','fault','offline') NOT NULL,
  fault_reason VARCHAR(64),
  ts DATETIME NOT NULL, src ENUM('ipmi','probe'),
  KEY idx_machine_ts (machine_id, ts)
);

CREATE TABLE sessions (                     -- 时段（计时结果，按状态分型）
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  machine_id INT NOT NULL,
  state ENUM('online','fault','offline') NOT NULL,
  fault_reason VARCHAR(64),
  start_time DATETIME NOT NULL, end_time DATETIME NOT NULL,
  duration_hours DECIMAL(10,4) NOT NULL,
  ongoing TINYINT DEFAULT 0,
  KEY idx_machine_start (machine_id, start_time)
);
```

## 4. 核心逻辑

```
采集(5min):
  power_on     = ipmi_power_on（有 IPMI）或 up（兜底）
  machine_ok   = up == 1
  gpu_online   = 该机 DCGM 指标存在
  gpu_uncorrectable = DCGM_FI_DEV_UNCORRECTABLE_TOTAL 有新增
  xid_error    = DCGM_FI_DEV_XID_ERRORS（>0 即有 XID 错误）
  ib_link_ok   = IB 链路状态 == active
  ib_port_ok   = IB 端口状态 == active
  state = 全满足 ? online : (power_on ? fault : offline)
  fault_reason = 失守条件拼接（gpu_down / gpu_uncorrectable / xid / ib_link_down / ib_port_down / machine_down）
  防抖: 连续 2 点一致才翻转 → 写 power_snapshots + power_events
配对(每小时): 同状态连续段配对为时段；未闭合段标记 ongoing
月结/报表: 在线时长 = Σ online 时段(月内截断)；故障时长 = Σ fault 时段（按 reason 分组）；在线率 = 在线时长/月总时长
幂等:      快照/事件/时段唯一键防重，cron 重跑不双计
```

**示例**：某台机器 8/1 10:00 开机 → 8/2 03:00 IB 端口掉线（fault, ib_port_down）→ 8/2 09:00 恢复 → 8/5 18:30 关机
→ 在线 8/1 10:00~8/2 03:00 + 8/2 09:00~8/5 18:30；IB 故障 6h 单独统计，不计在线时长

## 5. 报表与看板（Superset）

| 看板 | 内容 |
|---|---|
| 总览 | 集群在线率、当前在线/故障/离线台数、月累计在线时长 |
| 机器明细 | 每台 8×H100：在线时长、故障时长（按原因）、在线率、翻转次数、当前状态 |
| 故障分析 | 按原因分组：XID / 不可纠正错误 / IB 掉线 / GPU 掉线 的机器清单与时长排行 |
| 事件流 | 上线/故障/离线事件时间线（fault_reason 标注） |
| 离线分析 | 长期离线清单（>7 天）、离线次数排行（掉电频率） |
| 项目汇总（可选） | 按项目在线时长与占比 |

## 8. 边界
- 计时精度 5 分钟采样，事件延迟 ≤10 分钟（防抖）
- **XID 语义**：`DCGM_FI_DEV_XID_ERRORS` 为最近错误码，0=无错误；出现→fault，恢复 0→online
- **不可纠正错误**：`DCGM_FI_DEV_UNCORRECTABLE_TOTAL` 为累计计数器，用"新增量"判定（对比上次快照），防历史累计误判
- **GPU 掉线**：驱动重启/GPU 未识别→DCGM 无数据→fault；驱动恢复→online
- **IB 采集缺失**：若未部署 IB exporter，条件 6/7 无法判定 → 默认视为满足并在快照标注（待补采），避免漏计
- 异常断电按"探测到离线"记录，时长不丢
- 快照持久化在 MySQL，不依赖 Prometheus 保留期
- 时钟偏差影响时长精度 → NTP 同步
